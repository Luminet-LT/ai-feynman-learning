# 讲义深度规格（课程大纲级内容标准）· 平台版

Read this file whenever generating, deepening or refactoring a course. 它规定**课程大纲怎么清点、讲义正文写到什么程度算合格、生成后怎么验证**。课程的「深度」由这份规格定义，不由篇幅或形容词定义。

> **v2 变更说明**：v1 定义了三级产物、旧版 9 要素与自检表；当前平台版已升级为 10 模块，并把**一次真实 19 级课程重构中验证过的操作规格**并入——来源分级与 PDF 工具链、定义/事实/例的编号页码标注与两级附加标记、节计划分组规则、覆盖矩阵字段与红区三态、题目与答案分离及出题自查、命名与双链纪律、每轮工作循环。新增内容都不是设想，是踩过之后写下来的。

## 为什么需要它

「讲解要详细」是形容词，模型会按最小成本交付；而脱离来源的「扩写」最后会被整批撤出——本机 learn 库 2026-09-12 就把 76 篇模型扩写「详细讲义」全部撤到 `_archive/模型扩写-v2-20260912.md`，理由是「在逐条核对教材章节前不再视为讲义内容」。所以深度只能靠两条硬约束：

1. **来源锚定**：每条课程大纲挂教材 / 官方文档 + 章节 + 页码或 URL；
2. **要素清单**：每节讲义必须写齐 10 个模块，缺一项即不合格。

## 一、三级产物（缺一级即未完成）

| 级 | 产物 | 位置 | 回答什么问题 |
|---|---|---|---|
| 1 | **课程大纲清单**（全量、含子点） | `10-调研/<主题>/知识点清单.md`（文件可沿用旧名） | 这一主题到底有多少内容要学 |
| 2 | **课表 + 覆盖矩阵** | `20-课程/<主题>/课程大纲.md`（或级别文件） | 按什么顺序学、每级几节、谁在哪 |
| 3 | **每节讲义正文** | `20-课程/<主题>/讲义/级别N-节M-<课程大纲>.md` | 这一节到底讲了什么 |

只交付 1、2 两份清单 = 只给了目录，**视为课程未完成**。这是「课程很浅」的头号结构性原因。

## 二、来源锚定

### 2.1 来源分级（按可核程度从高到低使用）

1. **本地可核原文**（开放教材 PDF / 官方文档 / 官方规范）——可以写带页码的完整讲义；
2. **在线可核来源**（作者官网免费版、arXiv 论文、机构公开讲义）——写讲义时标 URL 与获取日期；
3. **仅章节定位**（受版权且拿不到正文的教材）——只记录「作者 + 书名 + 章节或定理编号」，**不写细节、状态留 `待校订`**；
4. **搜索摘要级信息**（只拿到标题与目录）——必须写明「来源已定位、正文未核读」，不得据此展开推导。

**先盘一遍每一级的来源可得性**（哪些书有原文、哪些只有章节定位），因为它决定该级能达到的深度上限；把结论写进审计或覆盖报告，让用户知道哪些级别是红区。

### 2.2 工具链（PDF 正文提取）

- **提取器**：`pip install --user pypdf`（Python 3.8+；已验证可提取 LaTeX 生成的教材正文，且 PyPI 在受限网络下也可能可达）。
- **每本都要验一次**：① 页数；② 是否有书签（书签直接给出「章 → 节 → 页码」）；③ 抽 3~5 页看字符数，判断是否扫描版（字符数极低 → 需 OCR，别硬写）。
- **无书签的兜底**：扫描正文里的编号标题（`^\s*(Chapter\s+\d+|\d+(\.\d+){0,3})\s*[\.:]?\s+[A-Z]`），按页码归属到章；噪声大时只取章级。
- **Windows PowerShell 5.1 编码坑**：脚本文件必须存成 **UTF-8 with BOM**，否则中文会被按 ANSI 解析、脚本直接语法报错；而**写回 Markdown 时要用 UTF-8 无 BOM**（`[System.IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($false)))`），否则 frontmatter 被 BOM 污染。
- 抽取的正文与目录先放工作区临时目录（如 `_<主题>-refactor/`），**不直接塞进知识库**。

### 2.3 标注粒度（核心：编号 + 页码）

每个知识点在讲义里必须能落到**编号 + 页码**，四类对象分别记：

| 对象 | 记法 | 例子 |
|---|---|---|
| 定义 | 「定义 X.Y（…，p.N）」 | 定义 1.3（子集，p.26） |
| 定理 / 事实 | 「定理/事实 X.Y（p.N）」 | 事实 1.5（除法算法，p.44） |
| 例 | 「例 X.Y（p.N）」 | 例 1.5（p.26–28） |
| 公式 / 编号式 | 「式 (1.1)（p.N）」 | 式 1.1（p.46） |

**两级附加标记（不得混用）**：

- `[推导·依据 定义 X.Y]`：**由来源定义直接推出**的结论（如 $\varnothing\subseteq A$、$|P(A)|=2^n$、De Morgan 律的雏形）。不是原文，但依据可追。
- `[模型补充·待核]`：**模型自己补的内容**（类比、额外例子、来源未讨论的变式）。可以写，但必须标，**不得套用「教材说……」的句式冒充来源**。

### 2.4 提取缺陷与降级（必须显式声明）

PDF 文本层丢符号是常态。遇到时在讲义里写清「哪一处是依语义还原、哪一处是原文」，例如：

> 提取说明：PDF 文本层未保留定义中的上划线，$\overline{A}$ 的写法依定义语义还原；等式 $=U-A$ 来自原文。

**凡与常见写法方向相反、或读起来可疑的原文表述，一律标「待核」并只采用无争议的那部分结论**，不得顺手按记忆「修正」原文。

## 三、课程大纲清单怎么来（不许凭空列）

1. **先取骨架**：教材目录 / 官方文档目录 / 认证考纲 / 课程教学大纲的章节树（章 → 节 → 子节），保留层级编号。搜索用「<主题> 教材 目录」「<主题> table of contents」「<主题> 官方文档 index」「<主题> syllabus」「<主题> 考试大纲」。
2. **建教材逐节整理总表**（有多本来源时必做；范式见本机 learn 库 `_meta/教材逐节整理总表.md`）：

   | 领域 | 主教材 | 章节 | 备用/校核 |
   |---|---|---|---|
   | … | 书名 + 作者 | Ch. x–y | 用于交叉核对的书 |

3. 每个节点抄成一条课程大纲，**一条一义**；再补「多处来源都提到、但目录里没有」的点，标 `[补充]`。
4. **状态只用四个受控值**：`待校订`（只有章节定位）/ `已校订`（逐段对应来源）/ `已写讲义`（讲义过自检表）/ `本课不覆盖（原因）`。
5. **至少两份来源交叉核对**：主教材定顺序，备用来源查漏；某来源独有的点要显式列出。

---

## 四、章节与节计划的分组规则

「节」是讲义的交付单位，**一节 = 1~3 条课程大纲**。分组规则：

1. **按章边界分组，不跨章**：一节内的课程大纲必须来自同一章；
2. **节数 = 真实分组数**，**不得用 `ceil(课程大纲总数 ÷ 3)` 估算**——实测差得很远（84 个节的教材，估算 28 节，按章内分组实际 **33 节**）；
3. 每一节都要能写出：**节号 + 教材章 + 课程大纲标题 + 页码范围**；
4. 节号与讲义文件名一一对应（`级别N-节M-<课程大纲>`），课表保留「节 → 讲义文件」列，未写的填 `—`；
5. 若旧课粒度比节更细（一课一知识点），**保留旧课但对齐到所属节号**（如两节课同属 S05，命名为 `L01-S05-数学陈述`、`L01-S05-逻辑联结词`），并在课表注明「节内分课，合并为一节一讲义待做」。

## 五、覆盖矩阵（缺项必须可见）

字段（逐级一行）：

| 级别 | 名称 | 课程大纲来源 | 章数 | 已展开节数 | 计划节数 | 已写讲义 | 覆盖率 | 状态 |

规则：

1. **没有任何课程大纲可以没有归属**：要么挂在某一级某一章某一节，要么显式写「本课不覆盖（原因）」；
2. **覆盖率 = 已写讲义数 ÷ 计划节数**，写进矩阵与课程总览；不足 100% 必须列出剩余项与原因；
3. **状态要区分三种「不可写」**，不要一律叫红区：
   - **真红区**：该级依赖的来源完全拿不到（受版权专著无正文）→ 只能章节定位；
   - **专著红区但论文可补**：经典专著拿不到，但 arXiv / 官方论文可核（前沿类级别常属此类）；
   - **论文驱动 / 派生级**：如「前沿论文阅读」「研究级」，本来就不按知识点计数，写明交付方式即可，**不虚报节数**；
4. 覆盖检查**逐行核对**，不是按「清单条目」看总数。

## 六、讲义深度规格（每节必须写齐 10 个模块）

1. **学习导航**：预计时间、前置知识、可观察目标、掌握标准、目标掌握程度。
2. **课前检索**：至少 2 个先回忆问题及回答提示，先作答再看讲解。
3. **问题情境**：真实场景、核心问题、常见错误直觉。
4. **概念建构**：白话定义、带来源页码/URL 的形式化定义、为什么需要、至少 3 步机制/推导、边界与反例。
5. **完整示范**：专家思路、至少 3 步推理、检查方法、至少 2 个例题。
6. **渐隐练习**：至少 2 题，每题写清题干、缺失步骤和提示；课堂模式必须提供作答入口。
7. **变式与错误诊断**：近迁移 + 远迁移；至少 2 条错误表现、原因、修正和自检。
8. **提取练习**：至少 2 个不看讲义先回答的问题；课堂模式提供作答入口。
9. **费曼输出**：明确本节费曼问题、至少 3 个必须包含的要素、提交入口、反馈和追问。
10. **小结、迁移与复习**：至少 3 条小结、一个迁移任务、前后连接和 1-3-7-15 复习安排。

硬规则：

- 本节覆盖 1~3 条课程大纲，超过 3 条要拆节。
- 定义、事实、例题尽量保留来源编号和页码/URL；无法核读正文标 `待校订`。
- 例题、机制、边界、反例和常见错误不得为空。
- 不得使用“略”“暂无”“简而言之”等占位内容。
- 课堂模式显示练习与费曼输入；讲义预览只显示已作答内容和已有评价，不显示空输入框。
## 七、生成流程（逐章生成，章内逐节完整）

平台按章解锁，不一次性生成整门课：

1. 从课程结构中取第一个尚未生成的章。
2. 只读取该章的课程大纲、相关报告章节和相关来源。
3. 为该章计划中的每一节写完整 10 模块讲义和 3 道单选 + 1 道开放题。
4. 跑 §八自检表；不过关就补写或重新生成，不许发布。
5. 保存讲义、题目、答案与来源定位，更新覆盖矩阵和课程状态。
6. 首章完成后即可开始学习；当前章完成前不生成下一章。
7. 章节调整必须说明影响范围；不得一次重写整门课。

> 为什么不整门课一次生成：整门课输出必然被压缩成摘要，且一处失败会污染全部内容。逐章生成能在质量和 Token 之间取得平衡。

## 八、讲义自检表（生成后逐项打勾，缺一不可）

- [ ] 模块 1 学习导航：时间、前置知识、可观察目标、掌握标准和目标掌握程度齐全
- [ ] 模块 2 课前检索：至少 2 个先回忆问题与提示
- [ ] 模块 3 问题情境：真实场景、核心问题和常见错误直觉齐全
- [ ] 模块 4 概念建构：白话定义、形式化定义、为什么需要、机制、边界与反例齐全
- [ ] 形式化定义带来源编号 + 页码/URL，或明确标 `待校订`
- [ ] 模块 5 完整示范：至少 3 步推理、检查方法、至少 2 个例题
- [ ] 模块 6 渐隐练习：至少 2 题，有缺失步骤与提示
- [ ] 模块 7 变式与诊断：近/远迁移各至少 1 题，错误诊断至少 2 条
- [ ] 模块 8 提取练习：至少 2 个不看讲义先回答的问题
- [ ] 模块 9 费曼输出：明确问题、至少 3 个必含要素和提交入口
- [ ] 模块 10 小结复习：小结、迁移、前后连接和 1-3-7-15 安排齐全
- [ ] 题目为 3 道四选一 + 1 道开放题；答案不随题目给出
- [ ] 正确项唯一、字母分散、相邻题不重复
- [ ] 模型补充标 `[模型补充·待核]`；提取缺陷已声明
- [ ] 本节课程大纲 1~3 条；编号与覆盖矩阵一致
- [ ] 覆盖率与讲义状态已更新

## 九、题目与答案（v2 新增）

### 9.1 分离规则（学习者看题、教练留答案）

- **题目（含选项）写在讲义里**，或 `40-练习与错题/<主题>/级别N-节M-题目.md`——**必须让学习者看得到题**；
- **答案、解析、思考题参考思路只写进** `级别N-节M-答案.md`（或知识库的「教练区」目录）；
- 讲义里只写「先作答，再看 [[…答案]]」，**不得出现答案、解析或折叠块**。

> 实战踩坑：曾把题目只写进答案文件，结果学习者根本看不到题——分离的是**答案**，不是题目。

### 9.2 出题后的自查（每次必须跑）

1. **正确项必须唯一**：逐题确认其余三个选项明确错误（实战出现过两个正确项）；
2. **正确字母分布要散**：避免集中在 1~2 个字母，**禁止相邻题目同字母**；出完自查一遍序列，不合格就重排选项顺序（实战例：`B B A C B B` → 重排为 `B D C A B D`）；
3. 干扰项要「像真的但明确错误」，不出现「两个都对」或「对错模糊」；
4. 每组配 1~2 道思考题，参考思路**只在作答后**给；
5. 改过选项顺序后，**回头核对答案文件与讲义一致**（最容易漏的一步）。

## 十、命名与双链纪律（v2 新增）

1. **双链用精确文件名**：`[[级别N-节M-知识点]]`，**Obsidian 区分大小写**，不要在同库混用变体（`L01-S01-…` 与 `l01-S01-…` 会变成两条链接）；
2. **改名 / 重编号时必须同步**：① 文件名；② frontmatter 的 `title`；③ 全库所有引用（索引页、课表、答案文件的 Relations）；④ 改名后跑一次**残留旧名检查**（`grep` 旧名，确认只剩历史记录）；
3. **遵循目标库自己的规范**：若知识库已有约定（如 `title/type/permalink/domain/status/updated/tags` + `Observations`/`Relations` 语义块），**照它的写**；规范若写明「permalink 一经建立尽量保持稳定」，则改文件时**保留原 permalink**；
4. 目录与文件名用中文、不用空格（用 `-` 连接）；级别用 `级别N`/`L0N`，节用 `节M`/`S0M`，全库保持一致。

## 十一、每轮工作循环与交付（v2 新增）

一次「生成轮」= 一章；章内每节必须完整，收尾必须做完这六件事：

1. 按章写完全部计划节的讲义（每节 10 模块 + 来源标注）；
2. 写题目与答案（分离、过 §9.2 自查）；
3. 更新**知识点清单状态**（相关知识点 → `已写讲义`）与**覆盖矩阵**（已写讲义数、覆盖率重算）；
4. 在 `来源核验与生成报告.md` 追加一行：本轮写了什么、依据什么、哪些待核、覆盖率达到多少；
5. 重建索引（若库有索引）；
6. 向用户报告**覆盖率变化**（本级 x/y、全库 x/y）+ 本轮自查修掉的问题。

**禁止**为了追进度一次性生成整门课；一次只生成一个章，下一章必须等当前章完成。

## 十二、什么时候算「够深」

三个可验收信号，全部满足才算交付：

1. 覆盖矩阵覆盖率 100%，或有显式「本课不覆盖 + 原因」；
2. 每节讲义过了自检表，且每条课程大纲对应的形式化定义带编号 + 页码；
3. 学习者拿这一节讲义**能独立做对配套自测题并说出为什么**——做不到就是深度不够，回第 4 要素补讲。

---

## 十三、已有课程 / 旧课的补深与重构流程

对已生成但只有大纲的课程（或「太浅」的旧课）：

1. **先体检**：用知识点清单与覆盖矩阵列出缺项清单——这是改造的输入，**不要凭感觉补**；
2. **按「来源能拿到什么」排序**：有本地原文的优先（可核读），只有搜索摘要的排后面，红区级别最后做且只做章节定位；
3. **对齐编号**：旧课编号与课程结构不一致时，先重编号对齐（§十第 2 条），再补新节；
4. **逐节补讲义**（每次一节），每补一节更新矩阵状态与覆盖率；
