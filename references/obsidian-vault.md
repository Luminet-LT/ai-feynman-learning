# Obsidian 文件库（平台离线副本）

Read this file only when the user asks for an offline/Obsidian knowledge base or when the web platform is unavailable. 平台优先以数据库为单一事实来源；文件库必须复刻平台当前的七阶段流程与 10 模块讲义，不得使用旧五步或旧 9 要素。

## 为什么要有这个库

调研是一次性的劳动，知识库是长期的资产：课程要能追溯到调研来源，上课时要能回头查讲义，学完后错题、费曼输出、补充资料还留在同一个地方。

文件模式默认根目录：**`D:\obsidian`**（若用户另行指定路径，以用户为准，并在课程信息里写明实际路径；平台模式不强制建库）。

**权限提示**：该路径通常在工作区之外，Codex 在 workspace-write 模式下会拒绝写入（写工作区外的路径需要提权）。此时用提权方式执行写入（`sandbox_permissions: require_escalated`），或请用户确认/调整路径；**不得静默改写到别处**。建库前先确认目录可写（不存在则创建）。

## 目录结构

```text
D:\obsidian\
├── 00-首页/
│   ├── 学习总览.md              # 所有课程的索引页：每门课一行 + 双链
│   └── <主题>地图.md            # 单门课的 MOC：调研 / 课程 / 讲义 / 练习 / 日志全在这里串起来
├── 10-调研/<主题>/              # 生成课程前联网调研的落地（课程的唯一事实来源）
│   ├── 调研总览.md              # 主题、学习目标、时间预算、调研日期、来源可信度说明
│   ├── 知识点清单.md            # 全量知识点：章 → 节 → 子节，保留层级编号 + 状态
│   ├── 教材逐节整理总表.md      # 主教材定序 + 备用教材查漏（+ 章节 / 页码）
│   ├── 重点清单.md              # ▲ 重点，每条写出处（至少 3 个来源覆盖的才列）
│   ├── 难点清单.md              # ★ 难点 + 大家为什么卡 + 应对办法
│   ├── 参考项目.md              # 5~8 个真实项目：名称 / 一句话 / 难度 / 链接
│   ├── 来源核验与生成报告.md    # 每轮写了什么、依据什么、哪些待核（含覆盖率）
│   └── 来源卡片/
│       ├── <来源名>.md          # 一来源一卡：类型、链接、关键结论、获取日期
│       └── ...                  # 课程大纲、教材目录、考试大纲、社区路线、卡壳记录……
├── 20-课程/<主题>/
│   ├── 课程总览.md              # 目录 + 总览表（级别 × 学习目标 × 难度 × 掌握程度 × 时长 + 覆盖率）
│   ├── 课程大纲.md              # 顶部覆盖矩阵 + 级别/章/节结构 + 复习与费曼任务
│   └── 讲义/                    # ★ 课程主体：每节一个文件，10 模块正文
│       ├── 级别1-节1-<知识点>.md
│       └── ...
├── 30-练习与错题/<主题>/
│   ├── 级别N-节M-题目.md        # 只有题目与选项（学习者看的）
│   ├── 级别N-节M-答案.md        # 教练留档：答案 / 解析 / 思考题参考思路（作答后才揭晓）
│   └── 错题本.md                # 错题 + 错因 + 回扣复习安排
└── 40-学习日志/<主题>/
    └── 级别N-日志.md            # 本轮的费曼输出 / 卡壳点 / 自检 / 教练反馈
```

命名规则：目录与文件名用中文、不要空格（用 `-` 连接），一笔记一主题；级别用 `级别1`、`级别2`……，节用 `节1`、`节2`……，便于排序。

## 笔记规范

- **frontmatter 必写**（方便 Obsidian 检索与 Dataview 汇总）：

```yaml
---
title: 调研总览
type: 调研            # 调研 / 知识点清单 / 教材总表 / 重点清单 / 难点清单 / 来源卡片 / 课程 / 讲义 / 题目 / 答案 / 日志
topic: <主题>
course_level:         # 课程、讲义、题目、答案、日志类笔记填级别号，如 3
lesson:               # 讲义与题目类笔记填节号，如 4
points:               # 讲义类笔记列出本节覆盖的知识点编号，如 [3.2.1]
source: <链接或书名>   # 来源卡片与讲义必填（讲义要带章节与页码）
status: 待校订         # 待校订 / 已校订 / 已写讲义 / 本课不覆盖
date: <YYYY-MM-DD>    # 内容获取/撰写日期（时效性信息尤其重要）
tags: [学习课程, <主题>]
---
```

- **status 只用四个受控值**：`待校订`（只有章节定位，正文未核读）/ `已校订`（逐段对应教材章节）/ `已写讲义`（讲义过了深度自检）/ `本课不覆盖（原因）`。**模型扩写不得标成已校订**。
- **用双链而不是复制粘贴**：调研笔记 → 课程 → 讲义 → 题目 → 日志之间用 `[[笔记名]]` 互链；`<主题>地图.md` 是总入口。
- **来源必须可核**：来源卡片与讲义里的教材引用写「书名 + 章节 + 页码」或 URL + 获取日期；搜不到可靠来源就写「未经联网核实」，**不得编造链接**。模型自己的补充一律标 `[模型补充·待核]`。
- **答案与题目分文件**：答案、解析、思考题参考思路只写进 `级别N-节M-答案.md`；学习者手上只有题目文件，符合「先做后对」。
- 一条一义：一条知识点就一条，不要把整段课程塞进知识点清单。

## 建库步骤（用户要求离线库、导出，或平台不可用时）

1. 创建目录骨架（00-首页 / 10-调研 / 20-课程（含讲义子目录） / 30-练习与错题 / 40-学习日志）。文件库对应平台的“资料收集 → 可编辑报告 → 课程结构 → 首章讲义 → 开始学习”阶段。
2. 写 `10-调研/<主题>/` 笔记：调研总览、**知识点清单、教材逐节整理总表**、重点清单、难点清单、参考项目、来源卡片（每个来源一张）。
3. 写 `00-首页/<主题>地图.md`（MOC）与更新 `00-首页/学习总览.md`（把新课程登记进去）。
4. 向用户报告：库路径、文件清单、每份笔记用途、课程大纲总数与待校订数量，并说明后续内容从这个文件库生成。

## 从文件库生成课程内容（文件模式）

文件模式与平台七阶段保持一致：

1. **课程大纲清单**：从用户确认后的调研报告抽取；每条挂来源、章节、页码/URL 和状态。该文件可沿用 `知识点清单.md` 文件名，但用户可见文案统一写“课程大纲”。
2. **课程结构**：在 `20-课程/<主题>/课程大纲.md` 顶部维护「级别 → 章 → 节 → 课程大纲」和覆盖矩阵；编号固定为 `级别.章.序号`，连续且不重复。
3. **首章讲义**：先生成第一章，验证可学习后开始；后续逐章生成，不一次性写完整门课。
4. **每节讲义**：按 depth-spec 的 10 模块写齐：学习导航 / 课前检索 / 问题情境 / 概念建构 / 完整示范 / 渐隐练习 / 变式与诊断 / 提取练习 / 费曼输出 / 小结复习。
5. 里程碑与动手练习优先改编自 `参考项目.md`，注明「改编自：xxx（[[参考项目]]）」。
6. 新结论或新来源先补进 `10-调研/<主题>/`（含日期）再写讲义；无依据内容标 `待校订` 或 `[模型补充·待核]`。
7. 用户编辑报告后重新生成结构时，旧讲义和题目需明确标记为失效或归档，用户上传资料不得删除。

## 库的维护

- 每次课程调整（级别增减、内容加深、时长变化）同步更新 `20-课程/<主题>/课程总览.md`、`课程大纲.md` 与覆盖矩阵，并在 `调研总览.md` 记一行变更说明（改了什么、为什么、从哪一级生效）。
- 每补完一节讲义，更新覆盖矩阵状态列与覆盖率，并在 `来源核验与生成报告.md` 记一行（写了什么、依据什么、哪些待核）。
- 每轮上课结束写 `40-学习日志/<主题>/级别N-日志.md`，错题并入 `错题本.md`；升级/留级时把结论写进日志。
- 学完后的 1-3-7-15 天收尾复习，连同各级费曼输出与错题清单，一起记在日志里，便于复习时直接按库翻。
- **撤出的内容要留档**：来源核对不通过、被撤下的内容移入 `_archive/` 并注明撤出原因（不得直接删，便于以后复核）。
